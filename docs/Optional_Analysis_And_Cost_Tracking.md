# Опциональный анализ и учёт стоимости

Статус: раздел 4 (учёт стоимости) **реализован** 2026-07-26. Разделы 1–3
(тиры и опциональный анализ) — по-прежнему идея, кода по ним нет: сначала
измеряем, потом решаем границу тиров.

## 1. Идея

Транскрипт делается всегда и автоматически. Анализ (NoteCard: summary,
теги, связи) — по явному выбору пользователя, а не по умолчанию на каждой
записи. Бесплатная квота на анализ ограничивает расход токенов, вход в
продукт остаётся бесплатным.

Мотивация из практики: для основного сценария — надиктовать мысль и скормить
её ИИ-собеседнику по ходу разработки — достаточно сырого транскрипта. Он
точен настолько, что партнёр по разговору всё понимает. Карточка в этом
цикле не участвует и сгорает впустую.

### Поправка к экономике

«Транскрипт бесплатно» честно только для on-device. Облачная транскрипция
Gemini тоже жжёт токены, причём аудио-токены дороже текстовых, и на длинной
записи облачный транскрипт обычно дороже одной карточки по её тексту.
Поэтому граница платного проходит не между «транскрипт / анализ», а между
«on-device / облако»:

| Тир | Что входит | Стоимость |
| --- | --- | --- |
| 0 | On-device транскрипт (`NativeSpeechAdapter`, ru-RU), поиск, плеер, skip-silence, экспорт LLM-бандла | бесплатно, безлимит |
| 1 | Облачный refine транскрипта — точность имён, терминов, пунктуации | бесплатная квота, дальше платно |
| 2 | Анализ: NoteCard, summary, теги, связи | бесплатная квота, дальше платно |

Квоту считать в **минутах аудио**, а не в токенах: это единственная единица,
которую пользователь наблюдает и контролирует.

## 2. Что уже готово в коде

Транскрипция и анализ разъединены архитектурно, переписывать пайплайн не
нужно:

- транскрипт — `GeminiTranscriptionAdapter` / `NativeSpeechAdapter`;
- анализ — отдельный путь через `AnalysisPort` →
  `WimmDomain/Workflows/ProcessingWorkflow.swift` и
  `WimmInfrastructure/Notes/NoteProcessor.swift`, где LLM вызывается уже
  по готовому тексту.

«Сделать анализ опциональным» = настройка + триггер, а не рефакторинг.

## 3. Что придётся доделать

1. **Лента без карточки.** Списки и заголовки во многом живут на `NoteCard`.
   Дешёвый заголовок без LLM уже есть — `naiveNoteCard` в
   `MetadataRepository`; он и становится основой бесплатного тира. Важно,
   чтобы карточка с `isProcessed == false` не рендерилась как «failed» —
   те же грабли, что ловили на импорте документов.
2. **Триггер анализа.** В HUD уже есть концепт Send / Done: **Send** = мысль
   ушла, только транскрипт; **Done** = закрыть сессию и разобрать её. Плюс
   кнопка «Разобрать» на любой старой заметке и батч-выбор.
3. **Квота против атомарного батча.** `ProcessingWorkflow.run` обрабатывает
   пачку атомарно — при ошибке весь батч уходит в `.failed`. Остаток квоты
   проверять **до** запуска и резать пачку по нему, иначе на исчерпании
   получим пачку `failed` вместо статуса «отложено».
4. **Ретро-анализ архива** — главный пожиратель квоты. Перед запуском
   показывать оценку «N заметок ≈ M минут квоты».

## 4. Учёт стоимости (реализовано 2026-07-26)

Расход теперь записывается. До этого — не записывался вообще: токены
выбрасывались на входе, транскрипция не логировалась.

### Как пользоваться

```bash
wimm-cli cost --days 30                  # сводка + разбивка по типам операций
wimm-cli cost --group-by note --limit 20 # самые дорогие заметки
wimm-cli cost --group-by day             # динамика по дням
wimm-cli cost --init-prices              # скелет прайс-таблицы по моделям из логов
```

Первый запуск покажет токены, но не деньги: прайс-таблицы нет.
`--init-prices` создаёт
`<App Support>/Wimm/config/model_prices.json` со списком моделей, которые
реально встретились в логах, и нулевыми ставками. Ставки заполняются вручную
из прайс-листа провайдера (USD за 1M токенов, поля `input` / `output` /
`audio_input` / `cached_input`). Нули — намеренно: пустая ставка даёт заметно
неправильный итог, а не правдоподобно неправильный. Модель без ставки
исключается из суммы и перечисляется отдельной строкой «нет цены» — неизвестная
цена никогда не считается нулём.

Таблица версионирована полем `version`: цены провайдеров меняются, и отчёт за
прошлый месяц должен говорить, какой таблицей он посчитан.

### Что где лежит

| Слой | Файл |
| --- | --- |
| Счётчики токенов, ключи атрибутов, словарь операций | `WimmInfrastructure/LLM/TokenUsage.swift` |
| `ModelResponse` (текст + usage) | `WimmInfrastructure/LLM/ModelProvider.swift` |
| Декодирование `usageMetadata` / `usage` | `WimmInfrastructure/LLM/RemoteLLMProvider.swift` |
| Привязка вызова к заметке (task-local) | `WimmInfrastructure/LLM/LLMCostContext.swift` |
| Лог транскрипции (облако и on-device) | `WimmInfrastructure/Adapters/TranscriptionCostLog.swift` |
| Прайс-таблица и арифметика | `WimmInfrastructure/Configuration/ModelPricing.swift` |
| Отчёт | `Sources/WimmCLI/Commands/Cost.swift` |

Инварианты, которые нельзя ломать (на каждый есть тест в
`Tests/WimmTests/CostAccountingTests.swift`):

- **Ключи `tokens_*` — часть формата лога.** Переименование тихо обрывает
  историю: `wimm-cli cost` парсит их обратно из JSONL.
- **`UnifiedEventLogger` редактирует любой атрибут, в имени которого есть
  `token`.** Счётчики выживают только благодаря явному списку-исключению
  `usageCounterKeys`. Без него все цифры писались бы как `<redacted>` —
  и это было бы незаметно, пока кто-нибудь не открыл лог руками.
- **`audio_tokens` и `cached_tokens` — часть `prompt_tokens`, а не добавка.**
  Оба провайдера отдают их как разбивку. Сложение задвоило бы самую дорогую
  модальность.
- **Отсутствие счётчиков ≠ ноль.** `usage == nil` означает «неизвестно»;
  бесплатным считается только явный `engine == "on-device"`.
- **`$/минуту` считается только по облачным минутам.** On-device минуты
  показываются отдельной строкой; если подмешать их в знаменатель, платная
  минута будет выглядеть дешевле, чем она есть.

### Известный пробел

Живой WebSocket-стриминг (`GeminiLiveTranscriptionAdapter`,
`BidiGenerateContent`) в учёт не попал — у него другой протокол и нет
ответа с `usageMetadata` в том же виде. Батч-транскрипция, карточки и OCR
учитываются полностью.

### Что было (для истории)

- `WimmDomain/Logging/UnifiedEventLogger.swift` — JSONL-лог по дням,
  ротация, редакция чувствительного текста. Запись `kind: "llm"` уже несла
  `model`, `provider`, `origin`, `phase` (request/response), `correlation_id`
  и произвольные `attributes`. Запись в лог идёт всегда; флаг
  `llmLoggingEnabled` гасит только тела промптов, не метаданные.
- `WimmInfrastructure/LLM/LLMLogger.swift` — обёртка `logRequest` /
  `logResponse`, парой связанных по `correlationId`. Через неё уже проходили
  `LLMJSONClient` (анализ, карточки) и `OCRProviders`.
- `WimmInfrastructure/Notes/TranscriptionLog.swift` — пишет
  `audioDurationSec` по каждому прогону транскрипции.
- `wimm-cli stats` — считает объём библиотеки и суммарную длительность.

Три дыры, которые закрыты:

1. **Счётчики токенов выбрасывались.** `GeminiResponse` и
   `OpenRouterResponse` декодировали только текст.
2. **Путь транскрипции не логировался вообще** — `GeminiTranscriptionAdapter`
   ходит в API напрямую через `URLSession`, мимо `LLMLogger`.
3. **Не было прайс-таблицы и агрегатора.**

### Зачем это до продуктового решения

Тиры и размер бесплатной квоты нельзя калибровать на догадках. Теперь по мере
накопления логов появляются реальные числа по собственному паттерну
использования: сколько в месяц стоит «всё в облако», сколько — «транскрипт
on-device + анализ по выбору», и на какой минутной квоте типичный пользователь
остаётся бесплатным. Только после этого решение о границе тиров опирается на
факты.

Важное ограничение: учёт начинается с момента внедрения. Логи до 2026-07-26
счётчиков не содержат — `wimm-cli cost` честно сообщает, сколько таких
вызовов в периоде, и не пытается их оценить. Плюс ретенция лога по умолчанию
30 дней (`WIMM_EVENT_LOG_RETENTION_DAYS`), так что для годовой картины её надо
поднять заранее.

## 5. Открытые вопросы

- Квота на пользователя или на устройство? При CloudKit-синхронизации
  desktop + iPhone счётчик должен быть общим, иначе он обходится тривиально.
- Считать ли повторный анализ (reprocess) заново — и надо ли давать
  бесплатный ретрай после неудачного разбора.
- Учёт ошибочных и оборванных вызовов: токены за отменённый запрос
  провайдер всё равно посчитает, значит и лог должен.
- Стоимость поиска и агентных ответов (`answer` в `AnalysisPort`) — это
  третий поток расхода, в тирах выше он не учтён.
