# Алёна (в коде `Vik*`) — один голосовой обмен в Studio

Решение пользователя 2026-11-06: обращение во время обычной записи, ответ в HUD
и вслух. Источники: `891202FC` (17:35), `2D363AFC` (17:39), `3D1AD14C` (17:43).
После критики принято ограничить реализацию одним обменом, без неявной истории и
новой поисковой архитектуры. Помощник начинался 2026-11-06 под именем «Вик»
(«Эй, Вик») и позже переименован в «Алёну»; в коде сохранены имена `Vik*`, ключи
`WimmStudio.vik*`, префикс логов `[Vik]` и каталог `Conversation/vik/`.

## Обращение и отправка

Включить запись и сказать «Алёна, …» («Эй» необязательно; live ASR пишет
«Алёна», «Алена», «Эйалёна», `VikRequest.address`). Другие падежные формы
(«Алёной», «Алёну») и «Алёнка» помощника не включают. HUD показывает вопрос
после обращения. В модель передаётся **весь финальный live-текст текущей
заметки**, включая мысль перед обращением. Предыдущие заметки и предыдущие
ответы автоматически не прикладываются.

Кнопка отправки, обычная Send и ⌥X закрывают текущую запись для ответа.
Автоматический путь использует то же событие `SilenceGate` / `SilenceSplitter`,
что обычные заметки: `captureSilenceSplitSeconds`, по умолчанию **10 секунд**
тишины после речи; 0 отключает этот путь. Обращение без вопроса не отправляется.
Событие тишины теряет актуальность после новой речи или смены файла.

**Короткая пауза возвращена 2026-11-11 (решение пользователя):** если в
заметке есть обращение с вопросом и микрофон молчит 1,5 секунды после речи,
запрос уходит, не дожидаясь 10 секунд. Пауза считается по уровню микрофона
(`SilenceGate.quietAfterSpeech`, тот же порог тишины), а не по неподвижности
live-текста. На обычные заметки без обращения это не влияет. Настройка
`WimmStudio.vikPauseSeconds` (UI нет; 0 отключает). Известная цена: пауза
на раздумье посреди вопроса длиннее 1,5 с отправит его недосказанным.
Вживую значение ещё не проверялось.

## Завершение live-текста

Запись закрывается через обычный CaptureSession; исходный AAC остаётся
сохранён, local-прогон по оригиналу по-прежнему ставится в очередь.
Пока финальный live-read не завершился, HUD показывает «завершаю live-текст»
и позволяет отменить запрос. Облако до этого не вызывается.

Финальный результат приходит отдельно с URL исходной записи, номером
действия захвата и явным успехом либо ошибкой. Черновик остаётся сохранённым
обычным путём, но **не считается успешным финальным результатом** для Алёны.
Если финальный текст исправил или дополнил вопрос, модель получает новую версию.

Ожидание ограничено 20 секундами. При ошибке, тайм-ауте, исчезновении обращения
из финального текста или заметке больше 64 000 UTF-8 байт запрос не отправляется.
HUD объясняет причину; аудио остаётся сохранено. Не происходит ни скрытого
обрезания текста, ни подстановки старого черновика. После ошибки запись
включается вручную. Поздний результат после отмены или тайм-аута ничего не запускает.

## Кто управляет микрофоном

Каждое явное start/stop/send в CaptureSession меняет `actionRevision` и
синхронно сообщает об этом контроллеру. Даже Stop при уже выключенной записи
отменяет ранее запланированный автоматический старт. Toggle отзывает старое
действие до постановки собственной задачи. Голос останавливается **до**
открытия микрофона, включая действия из HUD, меню, горячих клавиш,
документа, «Друга» и внешних команд.

Алёна может закрыть только ту запись и возобновить только тот захват, номер
действия которых не изменился. Она закрывает свою запись до перехода к следующей,
а не останавливает новую запись из callback старого ASR. Неожиданные результаты
других файлов игнорируются; очереди старых запросов нет.

Во время ожидания финального текста, ответа модели и озвучки микрофон выключен.
Это обмен по очереди: голосовое «стоп» в этот момент не слышно. В HUD показано
состояние микрофона; кнопка записи прерывает Алёну и начинает запись.
Автовозврат происходит только после окончания потока **и** озвучки, если Алёна
сама приостановила запись и пользователь не совершил нового действия.
Ручной Stop, отмена, ошибка или отказ озвучки не включают микрофон автоматически.

## Режим «в наушниках» (проба, 2026-11-11)

Меню: «Алёна: я в наушниках — не выключать микрофон»
(`WimmStudio.vikKeepMicOpen`, по умолчанию выключено). В этом режиме Алёна
микрофон не трогает вовсе:

- Заметка с обращением уходит как обычная — тишиной или Send; следующая
  заметка начинается сразу. Алёна ждёт финальный live-текст закрытого файла и
  отвечает; ответ привязан к этому файлу, а не к состоянию записи.
- Сказанное, пока Алёна думает и говорит, идёт в следующую заметку.
- «Стоп», «хватит» или «замолчи» в следующей заметке останавливают ответ
  (с задержкой live-текста, около 1–2 с). Слово остаётся в заметке.
- Новое обращение «Алёна» прерывает текущий ответ и становится новым запросом.
- Send следующей заметки ответ не прерывает; кнопки Start/Stop записи
  прерывают, как раньше.

Без наушников режим включать нельзя: голос Алёны запишется в следующую
заметку. Подавления эха нет. Правила аренды захвата (`ownsCapture`,
`actionRevision`) в этом режиме не применяются — Алёна ничего не закрывает и
не открывает. Проверено тестами (27 тестов); вживую ещё не проверялось.

## Ответ и личный контекст

Используется существующий `GeminiChatStream` / `LLMTransport`,
`ModelSelection.conversationModel` (по умолчанию `gemini-3.8-flash`),
`thinking: .lowLevel` (`VikAssistant.swift`) и потоковые предложения. Пока модель
ещё молчит до первого токена, звучат фиксированные локальные фразы без вызова
модели: `«Секунду.»` через 1,2 с и `«Ещё читаю, подожди.»` через 10 с
(`VikAssistant.acknowledgementPhrase` / `reassurancePhrase`). Параметр
`temperature` для Gemini 3.x не отправляется: используется выбор провайдера, как
рекомендует руководство Gemini 3.8. Выбранный уровень размышления сохраняется на
всех шагах чтения инструментов. В меню Studio есть переключатель обращения
`«Алёна — обращение «Алёна»»` (запоминается), выбор голоса `«Голос Алёны»`
F1–F5 / M1–M5 (**по умолчанию `F4`**, `VikVoice.swift`) и кнопка
`«Остановить ответ Алёны»`.

По решению пользователя от 2026-11-06 модель сама запрашивает контекст через
инструменты только чтения:

- `previous_note`: запись непосредственно перед текущей (без пропуска пустых).
- `notes_last_hour`: список записей за час перед вопросом, без текущей и более
  поздних; `read_note` читает найденные записи целиком, страницами с `nextOffset`.
- `document_outline`: оглавление открытого документа с ID заголовков.
- `document_section`: раздел с подразделами, постранично целыми блоками;
  `document_blocks`: отдельные блоки по тем же ID.

С 2026-11-12 первая страница `document_outline` и `notes_last_hour` читается
кодом заранее и уходит в первом запросе (`VikContextTools.preloaded`, лог
`context_preloaded_ms`): по логам 11–12.11 модель почти всегда тратила на них
два-три отдельных круга по 2–6 с. Те же проверки доступа и приватного режима,
оба чтения попадают в сохранённый «Прочитанный контекст». Остальное модель
по-прежнему запрашивает сама.

Оглавление, разделы и блоки читаются через `SecretaryDocumentReader`, заметки —
через `FileRepository`, `LibraryRecallSource.loadFiles`, `NoteRecall` и готовый
рендерер свидетельств `MCPRecallServer.readNote`. Проход секретаря не создаётся,
его отметки и границы не меняются. Пустые записи, варианты live/local/cloud и
происхождение текста не подменяются модельным пересказом.

Прежняя автоматическая подборка абзацев по совпавшим словам удалена.
Документ зафиксирован на начало обмена; ID не меняются при его перезагрузке.
Списки явно содержат preview, для фактов нужно читать саму запись или раздел.
Ссылки на запись `[N:UUID]` и блок `[b12]` остаются в тексте, но не озвучиваются.
Модель должна сначала читать предыдущую запись при явной ссылке на неё, а при
неустранимой неоднозначности — уточнять, а не угадывать.

С 2026-11-21 инструментов больше (см. «Алёна как агент» ниже): поиск по всей
библиотеке, поиск по документу, свои недавние ответы по запросу и вопросы
секретаря.

Один обмен ограничен восемью модельными шагами и шестнадцатью вызовами чтения;
каждая облачная попытка отдельно учитывается LLMLogger. Продолжения возвращают
оригинальные function-call parts с thought signatures и ID вызова. Перед и
после асинхронного чтения проверяются приватность и право текущего обмена;
перед следующим облачным запросом снова проверяется отмена и LLMTransport.
Это временный контекст одного вопроса, не неявная история разговоров.
У Алёны нет инструментов изменения файлов, выполнения команд и интернет-поиска.

Завершённый ответ, вопрос, весь использованный текст текущей заметки, исходный
путь и фактически прочитанные страницы контекста сохраняются атомарно в
StoragePaths.baseDirectory()/Conversation/vik/<UUID>.md.
Sidecar и личный документ помощник не редактирует.

## Задача для Claude Code (проба, 2026-11-11)

«Алёна, задача для кода: …» (также «для клода», «для Claude Code») и короткая
форма для скилла `idea-review` — «Алёна, идея: …» или «Алёна, идея» /
«запусти эту идею» / «проработай идею» после самой мысли (`VikCodeTask.ideaTask`)
— не идут в модель. После успешного финального live-текста Studio открывает ссылку
`claude://code/new?folder=…&q=…`: в приложении Claude появляется черновик
новой сессии Code с текстом задачи. **Ничего не запускается, пока пользователь
не нажмёт Enter** — это и проверка распознавания. Автозапуска нет по решению
пользователя «потестируем пока без автозапуска».

В черновик попадают: задача после фразы (для короткой формы — просьба
проработать идею), мысль из той же заметки до обращения (помечена как
контекст), относительный путь исходной записи и просьба работать в отдельной
ветке. Папка берётся из настройки `WimmStudio.vikCodeTaskFolder` (UI нет; без
неё приложение Claude само выбирает папку). Текст длиннее 4 000 знаков не
обрезается: Алёна сообщает, что задача осталась в заметке. Алёна говорит
короткое подтверждение, обмен сохраняется в `Conversation/vik/` как обычно,
запись возобновляется по общим правилам. В приватном режиме Алёна отказывает
как и раньше. Вместе с предложением секретаря ниже это два исключения вне
инструментов только чтения; команд она по-прежнему не выполняет. Логика:
`VikCodeTask` (`VikRequest.swift`), `codeTaskReply`.

Проверено 2026-11-11: ссылка в установленном приложении Claude открывает
черновик с текстом и не отправляет его; 25 тестов, 0 ошибок. Живое голосовое
обращение ещё не проверялось.

## Предложение запустить секретаря и правило тишины

Когда ожидающие заметки заполняют один пакет секретаря
(`SecretaryPassScan.pendingBytes` ≥ размера пакета), Алёна спрашивает один раз
на пакет, не запустить ли проход (`VikSecretaryOffer`,
`VikSecretaryOffer.shouldOffer` — повторный вопрос появится только после
накопления ещё одного полного пакета). На экране появляется баннер с кнопками
«Запустить» / «Не сейчас», а вопрос озвучивается (предложение действует 10 мин,
`VikSecretaryOffer.answerWindow`). Проход запускается только по кнопке,
короткому устному «да» на свежее предложение или прямой команде «Алёна, запусти
секретаря» (`VikSecretaryCommand.parse`) — без вызова модели и никогда кодом
самостоятельно; в приватном режиме отказывает.

Алёна никогда не перебивает пользователя сама (`VikAssistant.userIsQuiet`):
непрошеная реплика ждёт паузы — микрофон выключен, либо режим в наушниках и
после речи прошло не меньше 5 с тишины (`VikSecretaryOffer.quietBeforeSpeaking`).
Во время записи без наушников вопрос не озвучивается, чтобы голос не попал в
текущую заметку.

## Голос, приватность, проверка

Supertonic прогревается локально при запуске мониторинга, без платного запроса
к LLM. Первая загрузка может скачать и скомпилировать голосовую модель.
Пока он не готов, ответ читает установленный русский системный голос.
Если синтез или воспроизведение уже выбранного голоса отказали, HUD сообщает
«Не удалось озвучить. Ответ доступен текстом»; поток текста завершается,
а микрофон автоматически не возобновляется. Цепочки резервных голосов нет.
Отменённая очередь проверяет поколение до следующего синтеза.

В приватном режиме Алёна отказывает; смена режима во время запроса отменяет
старую работу. Сам `LLMTransport` отказывает всем облачным запросам в приватном
режиме (kill switch, без маскированного пути). Перед каждым продолжением
облачного потока после чтения режим проверяется снова.

Лог `[Vik]`: `capture_closed_ms`, `first_text_ms`, `first_audio_ms`,
`response_complete_ms`, `playback_complete_ms` от отправки и
`address_to_audio_ms` от обнаружения обращения (включает дальнейшее ожидание).
Это ещё не замер «конец произнесённого вопроса → полезный звук».
Новая связка инструментов проверяется на подменённом облаке, без платных
экспериментов. Реальные задержки и качество ответа после чтения контекста
этими проверками не измеряются.

Тесты подменяют облако/голос, проверяют задержанный и ошибочный финальный ASR,
тайм-аут и отмену, новую запись во время старой работы, запрет позднего
автовозврата, явный порядок остановки голоса и начала записи, отказ озвучки,
приватность и HUD в реальном NSWindow. Есть связка настоящего CaptureSession
с удерживаемым тестовым ASR; тестовая библиотека всегда временная.

## Алёна как агент (2026-11-21)

Цель пользователя: «сделай из Алёны полезного агента, используя новейшие
практики open и closed source агентов». Рамки AGENTS.md не менялись: только
чтение, никаких правок файлов и команд, нет неявной истории, приватный режим
отказывает. Платных проверок не было — всё проверено на подменённом облаке.

Что взято из практик и как применено:

- **Поиск по требованию вместо заранее собранного контекста** (Anthropic
  «context engineering», Claude Code: агентный поиск вместо индекса). Новые
  инструменты: `search_notes` — линейный поиск `NoteRecall` по всей библиотеке
  словами и/или датами (пустой `query` + `since`/`until` = «что я записал
  вчера»), `document_find` — поиск секретаря по документу сразу по нескольким
  темам с путём заголовков. `read_note` читает и найденные поиском записи.
  Текущая заметка своим же свидетельством не считается.
- **Время в запросе.** Первый запрос несёт `<now>` (день недели, дата, время,
  часовой пояс, ISO-день), иначе «вчера» и «в четверг» не к чему привязать.
- **Явное продолжение разговора без неявной истории.** `my_recent_replies`
  читает вопросы и ответы самой Алёны из `Conversation/vik/` за два часа до
  вопроса — только когда модель сама решит, что это продолжение («а подробнее»).
  Код ничего не прикладывает (`VikReplyLog`, тест
  `testRecentRepliesAreReadOnlyOnRequest`).
- **Вопросы секретаря.** `secretary_questions` — открытые вопросы из
  `secretary/review_queue.md` рабочей области открытого документа (тот же
  разбор `SecretaryReviewQueue`), без правки очереди.
- **Инструменты для агента, а не для API** (Anthropic «Writing tools for
  agents»): описания говорят, когда инструмент нужен; пустой результат и ошибка
  объясняют следующий шаг («попробуй другие слова», «используй ID как вернул
  search_notes»), плохая дата — ошибка модели, а не конец обмена.
- **Мягкое исчерпание бюджета** (OpenAI Agents SDK `max_turns`, Claude Code).
  `GeminiChatStream`: последний из восьми шагов и шаг после шестнадцати
  чтений идут с `toolConfig.functionCallingConfig.mode = NONE` — модель отвечает
  по прочитанному. Вызовы сверх бюджета получают ответ-ошибку, а не
  выполняются. Неизвестное имя инструмента возвращается модели с перечнем
  доступных, а не обрывает обмен. Ошибка «предел» остаётся только если модель
  и после запрета пытается читать.
- **Промпт голосового агента** (OpenAI Realtime prompting guide, Gemini Live):
  разделы «роль / что есть / как работать / достоверность / чего не делаешь /
  как говорить»; данные в метках `<current_note>`, `<already_read>`,
  `<question>`; явный шаг «сначала реши, нужен ли поиск»; параллельные чтения;
  1–2 повтора поиска другими словами, потом честное «не нашла»; при похожем на
  ошибку ASR вопросе — переспросить; главное — в первом предложении; даты
  по-человечески. Если просят действие — подсказка голосовых команд Studio
  («задача для кода», «идея», «запусти секретаря»), а не ложное «сделала».
- **Озвучка без ссылок.** Общая `VikAssistant.withoutCitations`
  (HUD-баннер и голос): `[N:…, b12]` в одной скобке и голый UUID записи,
  найденный в replay 2026-11-07, больше не читаются вслух.

Полная библиотека для поиска (`VikLibrary`) грузится как у `wimm-cli mcp`:
изменённые заметки строит дочерний `wimm-cli mcp-build`, свой дисковый кэш
`AgentState/VikRecallCache`, прогрев при обнаружении обращения (без вызова
модели), выгрузка текста (~150–190 МБ) после 15 минут без поиска. Без
установленного CLI поиска нет, инструмент говорит модели, чем заменить.
